# Переводы (Ф13)

Языки: **uk, pl, en, de, cs, ru**. Единственный источник правды — `LANGS` в `src/i18n.ts`. Каталоги — `i18n/<язык>.json`.

## Как пользоваться
```ts
import { t, pickLang } from './i18n.ts';
t('pl', 'role.teacher');                          // «Nauczyciel»
t('de', 'greeting.hello', { name: 'Anna' });      // «Hallo, Anna!»
t('uk', 'lesson.count', { count: 5 });            // «5 уроків»
const lang = pickLang({ query: '?lang', user: настройкаПользователя, acceptLanguage: заголовок });
```
Порядок выбора языка: `?lang=` → настройка пользователя → `Accept-Language` (с весами q, `pl-PL` → `pl`, `*` не считается) → `DEFAULT_LANG` (uk).

## Формат каталога
- Плоские ключи `раздел.имя` (`error.forbidden`, `role.owner`, `sos.sent`, …).
- Обычное значение — строка; подстановка `{name}`.
- Множественное число — объект форм `{ "one": "...", "few": "...", "many": "...", "other": "..." }`, обязателен `{count}`. Форма выбирается `Intl.PluralRules` по языку.
  Нужные формы: en, de — `one, other`; uk, pl, cs, ru — `one, few, many, other` (для cs `many` — дробные числа, но форма всё равно обязательна).

## Запасной язык
Нет ключа в запрошенном языке → берём `en` (`FALLBACK`) → нет и там → возвращается сам ключ (пропажа видна, а не пустая строка). Неизвестный язык = `en`. Неподставленный `{плейсхолдер}` остаётся как есть. Сторож не даёт такому случиться в репозитории: ключи во всех языках одинаковые.

## Как добавить ключ
1. Добавьте ключ **во все 6** файлов `i18n/*.json` (порядок значения не важен, набор — важен).
2. Одинаковые `{плейсхолдеры}` во всех языках.
3. Используйте `t(lang, 'ключ')` с литеральным ключом — сторож найдёт его в `src/` и проверит, что он есть.
4. `npm test` — `test/i18n.test.ts` скажет, что забыто.

## Как добавить язык
1. Добавить код в `LANGS` (`src/i18n.ts`) и файл `i18n/<код>.json` со ВСЕМИ ключами и формами из `Intl.PluralRules(<код>).resolvedOptions().pluralCategories`.
2. Сторож проверит набор ключей, плейсхолдеры и формы автоматически; тест списка языков (`test/i18n.test.ts`, первый) нужно обновить на новый список.
3. Если язык с особой диакритикой — добавьте проверку букв в тест «диакритика на месте».

## Что проверяет сторож (`test/i18n.test.ts`)
одинаковый набор ключей; нет пустых строк и заглушек (TODO, XXX, lorem…); одинаковые плейсхолдеры; все формы множественного числа по языку; ключи из `t('…')` в `src/` существуют; выбор языка; ответ сервера.

## В сервере
Ошибки API (`src/server.ts`): если клиент прислал `?lang=` или `Accept-Language` с поддерживаемым языком, в тело добавляются `message_localized` и `lang`. Без них тело ответа прежнее до байта; `error` (код) и статус не меняются — клиент ориентируется на код.

## Чего ещё нет
- Качество переводов не проверено носителем языка — нужна вычитка (особенно cs, uk, pl).
- Сторож видит только литеральные ключи `t(lang, 'ключ')`; динамические (`` `error.${code}` ``) он не проверяет — для них ключи `error.<код>` заведены вручную для всех кодов ошибок API, которые сейчас есть в `server.ts`; новый код ошибки надо добавлять в каталоги самому, иначе `message_localized` в ответе просто не появится.
- Нет языка в профиле пользователя (колонка в БД и настройка) — `pickLang` принимает `user`, но сервер его пока не передаёт.
- Локализованы только ошибки API; тексты `ScheduleError.message` / `MessageRejected.message` (внутри домена) остаются прежними.
- Нет интерфейса комнаты/SOS и согласий на клиенте — ключи `sos.*`, `consent.*`, `role.*`, `*.status.*` заведены заранее и пока используются только тестом.
- Нет форматирования дат/чисел по локали, нет правил рода (М/Ж) — у ключей статусов формы нейтральные.
- Каталоги читаются один раз при старте; смена файлов требует перезапуска.
