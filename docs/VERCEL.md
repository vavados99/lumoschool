# Ф16: можно ли переключить Vercel с `site/` на веб-каркас

**Вердикт: НЕТ, не переключено.** `vercel.json` не менялся (`outputDirectory: site`, сборки нет). Решение переключать или нет — Влада (ДА/НЕТ). Настройки Vercel не трогались, платные сервисы не ставились.

## Что мешает (по коду, не по догадке)

1. **База — файл SQLite.** `src/db.ts` открывает `new DatabaseSync(path)`; `src/config.ts` в prod требует `DATABASE_PATH` — файл, `:memory:` запрещён. У бессерверной функции Vercel файловая система только для чтения, кроме `/tmp`, а `/tmp` у каждого экземпляра свой и пропадает. Записи уроков, согласий, сообщений, журнал аудита потерялись бы или разошлись между экземплярами. Для школы с детьми это недопустимо.
2. **Каркас — долгоживущий процесс.** `src/server.ts` вызывает `createServer(...).listen(port, '127.0.0.1')`. Vercel так не запускает: нужна обёртка в функцию-обработчик под каждый маршрут, это уже переписывание точки входа, а не переключение папки.
3. **Состояние в памяти.** Лимит частоты (Ф19a), нарастающая задержка входа и всё, что держится в памяти процесса, на бессерверной платформе не работает: у каждого вызова может быть свой экземпляр, счётчики не общие.
4. **Живая выкладка.** Сейчас на Vercel отдаётся статический сайт (`site/`: главная, шрифты). Переключение `outputDirectory`/`framework` убрало бы его с адреса проекта, а API без базы отдавало бы пустоту или ошибки.
5. **Резервные копии и восстановление** (`src/backup.ts`, `src/restore.ts`) рассчитаны на файл базы на диске сервера; на Vercel их запускать негде.

## Минимум, чтобы честно работало

Любой из вариантов требует решения Влада (деньги/внешний сервис):

- **А (минимальный по правкам кода): отдельный сервер** — VPS или любой хост с постоянным диском (Node 24, `node src/server.ts`, `DATABASE_PATH` на постоянном томе, за HTTPS-прокси с `COOKIE_SECURE=1` и `TRUSTED_PROXY`, `npm run backup` по расписанию). Vercel остаётся только для статического `site/` и проксирует `/api/*` на этот сервер (rewrites в `vercel.json`). Нужно: платный хостинг + домен/сертификат.
- **Б: внешняя база** (например, Postgres/libSQL-сервис) + переписать слой `src/db.ts` и все запросы с `node:sqlite`, перенести состояние лимитов в общее хранилище, обернуть каркас в функции Vercel. Объём: большой; нужен внешний (скорее платный) сервис, миграции, повторная проверка изоляции ролей всеми тестами.

Пока ни А, ни Б не выбраны, Vercel остаётся на `site/` — статическом сайте, без пользовательских данных.

## Что нужно от Влада

Одно решение: **А** (платный VPS, меньше всего правок), **Б** (внешняя база, много работы) или **оставить как есть** до первых живых людей.
