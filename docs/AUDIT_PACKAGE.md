# Пакет для внешнего аудитора безопасности (ворота №8)

Платформа онлайн-школы английского: дети и взрослые, Польша/ЕС. Закрытый репозиторий `vavados99/lumoschool`, каталог `платформа/`. Документ самодостаточен: по нему можно понять систему, запустить тесты и знать, куда смотреть первым делом.
Состояние на 19.10.2026. Всё, что я не проверял сам, помечено **«не проверено»**. Внутренняя проверка Ф14 (Опус) — не внешний аудит.

## 1. Что за система и модель угроз

- Сервер на Node ≥ 24 без сторонних пакетов: HTTP/JSON (`src/server.ts`) поверх ядра доступа, база — один файл SQLite (`node:sqlite`), тесты — встроенный `node:test`.
- Роли (хранятся в `users.role`): **ученик** (student), **родитель** (parent), **преподаватель** (teacher), **владелец** (owner). Роль берётся из базы по сессии на каждом запросе, клиент её не присылает.
- Данные детей: имя без фамилии, дата рождения, контакты (отдельная таблица `contact_vault`), расписание, сообщения, согласия родителей. До 16 лет для записи нужно согласие родителя.
- Главные риски (то, что просим проверить):
  1. **Преподаватель видит контакты или «базу»** — должен видеть только учеников своих уроков, без контактов и без id/имени родителей.
  2. **Ученик видит чужих** — других учеников, чужие ветки сообщений, чужие согласия.
  3. **Родитель видит чужого ребёнка** — или ребёнка, которому уже 18.
  4. **Связь «взрослый–ребёнок» мимо платформы** — обмен телефонами/ссылками в чате, ребёнок один с преподавателем в комнате.
  5. **Утечка секретов** — `SESSION_SECRET`, пароли, ключи, значения в логах, ошибках, репозитории, копиях базы.
  6. Вторично: подбор паролей и блокировка школы чужим адресом, повышение прав подменой id в запросе, оракулы (по ответу можно узнать, что урок/человек существует), гонки (двойная запись, превышение лимита группы).
- Допущение: сервер за HTTPS-прокси (`COOKIE_SECURE=1`, `TRUSTED_PROXY`); сам TLS в код не входит (**не проверено** вживую, только тестами).

- **содержимое ответов** обходом всех GET-маршрутов от лица каждого участника на сценарии «все в комнате, все пишут»: преподаватель — ни одного контакта из сида, только ученики своих уроков (Kai/Kira; у второго преподавателя — свои), родитель без имени и id, окно доступа 2 ч закрывается; ученик — только он сам, ни чужих учеников, ни чужих реплик, ни чужих контактов; родитель — только свой ребёнок, ребёнок 18+ пропадает из списков, согласий, выгрузки и комнаты; владелец — чужие контакты только по `/api/contacts/:id`, текстов личных веток нет;
- глухие пути под сессией (неизвестный путь/метод, `GET /api/rooms/1/chat`, нечисловой id) → 403, не 404/500; запрещённый маршрут отвечает 403 без разбора тела.

**Расхождения матрицы и кода, найденные при сверке (Ф23):** прав сверх таблицы не найдено ни у одной роли. Четыре маршрута шире права в `role_permissions` (владелец на `GET /api/threads/:id` и `GET /api/export/:id`; ребёнок <16 на `GET /api/consents/:id` и `GET /api/export/:id`) — это не дыры: ядро отказывает независимо, а таблица выше фиксирует отказ. Единственная одноуровневая защита была у `GET /api/owner/scheduler` (только список ролей маршрута, обработчик не проверял) — добавлена проверка роли в обработчике. Также `GET /api/me`, `POST /api/logout`: прав в `role_permissions` нет вообще (достаточно сессии, возвращают только данные самого себя).

**Что сверка НЕ закрывает:** ячейки таблицы — по одному законному представителю каждой роли (ученик KidA/AdultD, родитель ParentA и т. д.), не по всем комбинациям возраста, замены преподавателя, нескольких родителей; границы окон (10 минут до урока, 2 часа после) — только частично; нагрузка/гонки — вне этой проверки.

**Проверка силы теста Ф23** (временные поломки, откат, повторный прогон — 19.10.2026): контакты чужих открыты всем ролям (маршрут + ядро) → 4 красных; родитель видит чужих детей → 1; преподавателю виден id/имя родителя → 1; ученик допущен в любую комнату → 2; окно доступа преподавателя не закрывается → 1; ученик видит всех учеников → 1; открыт только маршрут планировщика → зелёное (держит вторая линия, это и есть её смысл); открыты маршрут и вторая линия → 1. После отката: файл Ф23 38/38.

## 5. Как запустить и воспроизвести

Требуется Node ≥ 24 (`engines` в `package.json`; на машине проверки — доступны `node:sqlite` и запуск `.ts` напрямую). Установка пакетов не нужна — зависимостей нет. Все команды — из каталога `платформа/`.

```bash
# тесты (265 штук после Ф25; около 3 минут)
npm test                      # = node --test test/*.test.ts

# один файл
node --test test/isolation.test.ts

# демо-данные в файл (ТОЛЬКО не prod; пароли демо-пользователей известны: demo-password-NNN)
LUMO_MODE=dev DATABASE_PATH=/tmp/demo.sqlite npm run seed

# сервер локально (127.0.0.1:8787 по умолчанию; PORT=... меняет)
LUMO_MODE=dev DATABASE_PATH=/tmp/demo.sqlite PORT=8787 npm start
curl -s localhost:8787/healthz         # {"ok":true}
curl -s -o /dev/null -w "%{http_code}\n" localhost:8787/api/me   # 401 без сессии
```

Вход: `POST /api/login` с JSON `{"login": "...", "password": "..."}`; логины сида: `owner`, `teachera`, `teacherb`, `parenta`, `parentb`, `parentc`, `kida`, `kidb`, `teenc`, `adultd`. Имена полей `login`/`password` — по `src/server.ts` (обработчик входа); формат ответа и куки — см. тест «вход/выход…».

Переменные окружения (из `src/config.ts`):

| Переменная | Смысл |
|---|---|
| `LUMO_MODE` | `prod` \| `dev` \| `test`; **не задан = prod** (тогда без остальных переменных сервер не стартует) |
| `DATABASE_PATH` | путь к файлу SQLite; в prod обязателен и не `:memory:`; в dev/test по умолчанию `:memory:` (пустая база, сид бессмысленен) |
| `SESSION_SECRET` | в prod обязателен: ≥ 32 символов, ≥ 8 разных, без слов-заглушек и пробелов; в dev/test — случайный на запуск |
| `COOKIE_SECURE` | `1` обязателен в prod (HTTPS за прокси); тогда кука `__Host-sid` |
| `TRUSTED_PROXY` | IP прокси через запятую; пусто — `X-Forwarded-For` игнорируется |
| `PORT` (8787), `BACKUP_DIR`, `BACKUP_KEEP` (14), `RETENTION_MESSAGE_DAYS`, `RETENTION_LOGIN_ATTEMPT_DAYS`, `SCHEDULER` (`on`/`off`), `SCHEDULER_OUTBOX_MS`, `SCHEDULER_BACKUP_MS`, `SCHEDULER_CLEANUP_MS`, `SHUTDOWN_TIMEOUT_MS` | см. `src/config.ts` |

Prod-запуск на локальной машине — пример (значение секрета сгенерируйте сами, в репозиторий и в историю оболочки не кладите): `LUMO_MODE=prod DATABASE_PATH=... COOKIE_SECURE=1 SESSION_SECRET="$(openssl rand -hex 32)" npm start`. Такой режим в живом прогоне **не запускался** (но проверяется CLI-тестами `config.test.ts`).

Прочие скрипты: `npm run backup`, `npm run restore -- <файл копии>`, `npm run maintenance` (нужны `DATABASE_PATH`, для копии — `BACKUP_DIR`; подробности — `docs/BACKUP.md`).

## 6. Известные слабые места и что просим проверить

### 6.1 Известные слабые места (из `docs/ВОРОТА.md`, без смягчения)

1. **Внешнего аудита не было.** Ф14 — внутренняя проверка модели, не независимая.
2. **Фильтр контактов на регулярных выражениях**: обход транслитом, картинками, описанием словами возможен; ложные срабатывания на даты вида `01-02-2026`. Сообщения не шифруются. Замещающий преподаватель писать в ветки пока не может.
3. **Правило «двух взрослых» только для урока с ровно одной записью-ребёнком.** Группа из двух детей и одного преподавателя без родителя допустима (поднимается флаг `child_without_second_adult`, но не запрещает). Если у ребёнка нет родителя, 1:1 возможно только с владельцем в комнате.
4. **Лимит частоты и счётчики входа — в памяти одного процесса**, после перезапуска обнуляются, при нескольких процессах у каждого свои. Окно фиксированное (минута).
5. **Доставка уведомлений «минимум один раз»**: падение между отправкой и пометкой `sent` → повтор; защита от параллельного `processOutbox` только внутри процесса; `users.lang` нигде не выставляется через интерфейс; реальный канал доставки не подключён (только локальные стоки). Родитель не может отметить уведомление прочитанным.
6. **Родитель не верифицируется**: в коде только связь `parent_child`, заведённая владельцем; процедуры подтверждения опекунства нет. Отзыв одного из двух родителей снимает согласие у обоих.
7. **Данные на диске не шифруются.** Копии лежат на той же машине; вынос в ЕС и шифрование копий не настроены; нет контрольных сумм рядом с копией; данные между копиями теряются (до суток). Удалённое по просьбе остаётся в старых копиях до ротации (14 дней по умолчанию), после восстановления удаление надо повторять.
8. **Срок хранения и чистка по расписанию** в проде не настроены (встроенный планировщик есть, на сервере не запускался). С Ф25 чистка (`runRetention`) удаляет также чат урока старше 90 дн. (`CHAT_RETENTION_DAYS`) и строки `audit_log` старше 365 дн. (`AUDIT_RETENTION_DAYS`, не меньше 30) — **оба срока — предложение разработчика, с юристом не согласованы**. Чтобы это стало возможным, триггеры журнала заменены миграцией `005-audit-retention.sql`: UPDATE разрешён только для `actor_id`/`target_id` и только на 0 («обезличено»), DELETE — только пока «ворота» `audit_purge_gate.open = 1` (их открывает `runRetention` на время своей транзакции). **Это защита от ошибки, а не от злоумышленника с записью в файл базы: он может открыть ворота или снять триггер** (как и раньше мог снять триггер). Не проверено: чистка на большой базе (производительность `DELETE ... WHERE ts <` без индекса по `ts`). Планировщик пишет в журнал только сбои, успешные запуски видны косвенно; мониторинга и оповещений нет.
9. **Порог 16 лет и срок хранения 6 лет** взяты без юриста; текста согласия нет, только метка версии `2026-10-v1`; экран родителя не подключён к API. Нет политики конфиденциальности, договоров с обработчиками, DPIA, порядка уведомления об утечке, канала приёма запросов на экспорт/удаление.
10. **Остановка по SIGTERM** ждёт запросы в полёте до `SHUTDOWN_TIMEOUT_MS` (10 с), затем обрывает; проверено на медленном теле запроса, не под нагрузкой.
11. **Не проверено вживую**: работа за HTTPS-прокси (`COOKIE_SECURE=1`, `__Host-sid`, `TRUSTED_PROXY`) — только автотесты; режим prod; нагрузка и параллельные клиенты; восстановление на настоящем сервере; ротация `SESSION_SECRET`. Сервера, хостинга в ЕС и реального видео-провайдера нет — записей уроков не существует (флаг только фиксирует намерение).
12. **Остаточные пробелы тестов (по ВОРОТА.md)**: HTTP-негатив `POST /api/consents/<чужой ребёнок>` и подмена id внутри разрешённой роли закрыты в Ф23 (`f23-routes-matrix.test.ts`, 403 + нет побочных эффектов); преподаватель видит числовые id своих учеников и свои `teacher_id`; тест копии «б» чувствителен к нагрузке; повтор при `locked/busy` в `backupDb` отдельным тестом не проверен; `FileSink` не проверяет, что путь вне репозитория; `secret_check.sh` смотрит индекс и staged-дифф, историю коммитов и удалённый репозиторий — нет.
12а. **Удаление по просьбе (Ф25) — ограничения.** (1) HTTP-ручка `POST /api/erase/:id` — владелец и родитель; **ученик 16+ через HTTP удалить себя не может** (ядро это умеет, ручка роль `student` не пускает — просит владельца): намеренно минимально, чтобы случайный клик ученика не стирал аккаунт. (2) Родитель, стирающий **себя**, разрывает связь с детьми и отзывает их согласия — будущие записи детей снимаются. (3) Преподавателя и владельца ручка не стирает вовсе (403) — процесс не определён. (4) Итоговая строка журнала `data.erased` хранит id удалённого (доказательство, что удаление выполнено); остальные строки о нём получают `actor_id/target_id = 0`; **числовой id других таблиц (запись об уроке до `retain_until`) остаётся и позволяет связать** — пока не истёк срок 6 лет. (5) `target_id` обезличивается только у типов `student`, `person_data`, `user`, `consent`, `contact_vault`; новый вид записи журнала с id человека под другим типом останется необезличенным — список `PERSON_TARGET_TYPES` в `consent.ts` надо вести вручную. (6) Реплики других людей в чате урока не стираются (общий чат; стираются только реплики самого человека). (7) Резервные копии (п. 7) не затрагиваются. (8) Канала приёма просьбы, проверки личности просящего и срока ответа нет — владелец выполняет вручную.
